# Publisher (macOS)

`aisphere_sync.py` reads quotas from CodexBar, converts them to the format in [`docs/json-contract.md`](../docs/json-contract.md) and uploads `usage.json` through the target configured in `~/.config/ai-sphere/publish.json`: Bunny, S3/R2, HTTP/WebDAV, FTPS, SFTP, a command or a local folder ([`hosting/README.md`](../hosting/README.md)). It runs once and exits; `launchd` starts it every 10 minutes. No server is listening.

It uses only the Python standard library and runs with the system Python (`/usr/bin/python3`, 3.9), so it does not depend on pyenv or Homebrew Python.

## What each run does

1. `codexbar usage --format json`: quotas of the built-in providers.
2. `codexbar plugins fetch <id> --json` for each user plugin in the `plugins` setting, because `usage` leaves them out. Their secrets are passed from the Keychain (see [`codexbar-plugins/README.md`](codexbar-plugins/README.md)).
3. `codexbar config providers --json`: providers disabled in CodexBar are dropped at once.
4. Normalises with an **allow-list** of fields: e-mail addresses, organisations, plans and costs never leave the Mac.
5. Uploads the JSON through the configured target (`targets.py`), and saves a local copy and its state.

## Install

Requirements: CodexBar with its CLI (`codexbar`) and an upload target in `~/.config/ai-sphere/publish.json` with its secrets in the Keychain (see `hosting/README.md`).

```sh
mac/install.sh          # every 600 s (10 min)
mac/install.sh 300      # or every 5 min; minimum 300
```

This installs the LaunchAgent `local.ai-sphere.sync` for your user (needed to read the Keychain) and starts it. Agents installed under an older label are replaced. It runs at load and then every interval. **The LaunchAgent stores the absolute path of the script: if you move or rename the project folder, run `install.sh` again.**

The first time the script reads the Keychain from `launchd`, macOS may ask whether `security` can access the items: choose "Always Allow".

To remove it: `mac/uninstall.sh` (logs, state, config and Keychain items are kept).

## Manual use

```sh
/usr/bin/python3 mac/aisphere_sync.py --dry-run -v   # print the JSON, upload nothing
/usr/bin/python3 mac/aisphere_sync.py -v             # build and upload
/usr/bin/python3 mac/aisphere_sync.py --input out.json --dry-run   # from a saved CodexBar output
/usr/bin/python3 mac/aisphere_sync.py --publish-config other.json -v   # try another target once
/usr/bin/python3 mac/aisphere_sync.py --public-url   # print the URL the watch downloads
launchctl kickstart -k gui/$(id -u)/local.ai-sphere.sync     # run the agent now
```

## Optional settings (`~/.config/ai-sphere/sync.json`)

Every key has a default in the script; only write the ones you change.

```json
{
  "maxWindowsPerProvider": 3,
  "exclude": ["openrouter"],
  "names": {"opencodego": "OCGO"},
  "labels": {"claude/secondary": "FABLE"},
  "labelLanguage": "en",
  "plugins": ["helmcode-credits"],
  "pluginSecrets": {"CODEXBAR_PLUGIN_HELMCODE_CREDITS_SESSION_COOKIE": "ai-sphere-helmcode-cookie"},
  "codexbarPath": "/opt/homebrew/bin/codexbar",
  "codexbarTimeoutSeconds": 90,
  "uploadRetries": 2,
  "missingGraceHours": 24
}
```

- `exclude`: providers you do not want on the watch (besides those disabled in CodexBar).
- `names`: short name on the bezel.
- `labels`: label of one window. The key is `provider/windowId`, where `windowId` is `primary`, `secondary`, `tertiary` or the `id` of an `extraRateWindows` entry.
- `labelLanguage`: `en` (`WK`, `MO`, `DAY`) or `es` (`SEM`, `MES`, `DÍA`).
- `plugins`: CodexBar user plugins to fetch separately. Set it to `[]` if you do not use any.
- `pluginSecrets`: environment variable for CodexBar → Keychain item holding its value. If the value is a JWT, the log warns when it has less than 3 days left.

## Failure handling

| Situation | What happens |
|---|---|
| Another run is in progress | Exits without doing anything (`flock`). |
| CodexBar does not answer or returns no JSON | Nothing is uploaded; the CDN keeps serving the last file and the watch sees `t` getting older. |
| A provider fails | Its last good values are republished with `err: 1`. If it never had data, it is left out. |
| A provider is disabled in CodexBar | It leaves the JSON at once. |
| A provider disappears from CodexBar | Its last values are kept with `err: 1`, in the same position, for `missingGraceHours` (24 h), then it is dropped. CodexBar sometimes leaves out a provider whose API is failing. |
| A plugin secret expires | The plugin fails and the "provider fails" row applies. The log warns beforehand. |
| Network error while uploading | Retries twice (after 5 s and 10 s). No retry on errors that will not fix themselves (401/403/404, bad config, missing secret). |
| The Mac is off or asleep | The CDN keeps serving the last file. |

Local writes are atomic (temporary file + `rename`).

## Tests

```sh
/usr/bin/python3 -m unittest discover -s mac/tests   # normaliser and upload targets
node mac/tests/test_helmcode_plugin.mjs              # HelmCode plugin logic
hosting/test/integration.sh                          # every target against real servers in Docker
```

The normaliser tests run on a real CodexBar output: no personal data leaks, size under 2 KB, labels in both languages, Antigravity duplicates, pace, rounding, dates, failing and vanishing providers, disabled providers and plugins. The target tests cover config loading, secrets, retries, the local targets, HTTP/WebDAV against a local server and S3 request signing. They pass with Python 3.9.

## Troubleshooting

```sh
tail -f ~/Library/Logs/AI-Sphere/sync.log
launchctl print gui/$(id -u)/local.ai-sphere.sync | grep -E "state|last exit"
```

Each run logs lines like these:

```
INFO codexbar ok in 2.6s (exit 0, 3 providers)
INFO plugin helmcode-credits ok
INFO payload 610 bytes, 4 providers [CODEX:100%, CLAUDE:69%, AGY:100%, HELM:100%]
INFO uploaded 610 bytes -> my-zone/usage.json (HTTP 201)
```

The percentages are what is **left** of each provider's most used window.

| Message | Cause |
|---|---|
| `codexbar CLI not found` | `launchd` cannot see the binary: set `codexbarPath` in `sync.json`. |
| `Keychain item '…' not found` | The item is missing or macOS denied access: check Keychain Access. |
| `PUT failed: HTTP 401` / `S3 PUT failed: HTTP 403 …` | Wrong upload credentials for the target (see `hosting/`). |
| `no publish config` | Create `~/.config/ai-sphere/publish.json` (see `hosting/README.md`). |
| `SFTP failed: Host key verification failed` | Add the server to `known_hosts` once (`ssh-keyscan`). |
| `secret … expires in …` / `has expired` | Renew the HelmCode cookie (see `codexbar-plugins/README.md`). |
| `codexbar: … returned 500` | A provider failed inside CodexBar; informational. |
| `provider X has no data now` | Its last values were republished with `err: 1`. |

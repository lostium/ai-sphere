# S3-compatible storage

The `s3` target uploads with AWS Signature V4, so it works with any S3-compatible store: AWS S3, Cloudflare R2, Backblaze B2, Wasabi, DigitalOcean Spaces, Scaleway, Hetzner Object Storage, MinIO, Ceph… It stores `Content-Type: application/json` and `Cache-Control: private, max-age=60` with the object, and S3 replaces objects atomically.

Status: tested end to end (upload, then a signed read-back with the right content type and cache header) against an S3-compatible server in `hosting/test/integration.sh`. The providers below have not been tried individually.

**A bucket cannot check the `X-Key` header by itself.** Keep the bucket private and put something in front that does:

| Store | What to put in front |
|---|---|
| Cloudflare R2 | Custom domain + WAF rule: see [`cloudflare/README.md`](cloudflare/README.md#option-b-r2--custom-domain--waf-rule). |
| AWS S3 | CloudFront with Origin Access Control, plus a CloudFront Function on *viewer request* that returns 403 when `x-key` is wrong (below). |
| Backblaze B2 | Cloudflare in front (B2 and Cloudflare have free egress between them) with a WAF rule, as for R2. |
| Others | A CDN with header rules (Bunny, Cloudflare, Fastly), or a web server proxying the bucket (see [`web-server/`](web-server/)). |

## Config

```json
"target": {
  "type": "s3",
  "endpoint": "https://s3.eu-west-1.amazonaws.com",
  "region": "eu-west-1",
  "bucket": "ai-sphere-RANDOM",
  "key": "usage.json",
  "virtualHosted": true,
  "accessKeyId": "keychain:ai-sphere-aws-access-key-id",
  "secretAccessKey": "keychain:ai-sphere-aws-secret-access-key"
}
```

| Provider | `endpoint` | `region` | `virtualHosted` |
|---|---|---|---|
| AWS S3 | `https://s3.<region>.amazonaws.com` | the bucket's region | `true` |
| Cloudflare R2 | `https://<account-id>.r2.cloudflarestorage.com` | `auto` | `false` |
| Backblaze B2 | `https://s3.<region>.backblazeb2.com` | e.g. `eu-central-003` | `false` |
| Wasabi | `https://s3.<region>.wasabisys.com` | e.g. `eu-central-1` | `false` |
| DigitalOcean Spaces | `https://<region>.digitaloceanspaces.com` | e.g. `fra1` | `false` |
| MinIO / self-hosted | your server's URL | `us-east-1` unless configured | `false` |

Use credentials limited to this one bucket (write access to `usage.json` is enough).

## AWS: CloudFront function for the `X-Key`

CloudFront → Functions → Create (runtime `cloudfront-js-2.0`), publish, and associate it with the distribution's *viewer request* event. Replace `CHANGE_ME` with your secret:

```js
function handler(event) {
  var key = event.request.headers["x-key"];
  if (!key || key.value !== "CHANGE_ME") {
    return { statusCode: 403, statusDescription: "Forbidden" };
  }
  return event.request;
}
```

The object's `Cache-Control: private, max-age=60` keeps CloudFront from storing a shared copy, which is what you want for a keyed file with a few hundred requests a day. Untested here.
